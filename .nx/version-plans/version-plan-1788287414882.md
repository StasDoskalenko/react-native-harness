A platform package can now adjust the Metro config the harness composes, via a `metroConfigEnhancer` module it points at. The harness imports that module while building the config for the selected runner and lets it apply further changes (a `resolver` redirect, extra `resolver.platforms` entries, its own `InitializeCore`, …). This is the seam an out-of-tree platform such as React Native Windows or macOS would use for the Metro wiring `react-native start` gets from `@react-native/community-cli-plugin`, which the harness bypasses. Nothing changes for platforms that do not set one.
